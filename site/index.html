The hard question first

Where does a fast, bounded decision belong?

Most Jev conversations start at the API. The useful work happens earlier. Separate exact rules from semantic judgment. Bound the answer before inference. Keep the action and fallback in code.

First principles

Use Jev for a narrow semantic decision that software can safely act on.

It fits when

  • The decision repeats or sits on a critical path
  • The answer space is bounded before the call
  • Code cannot decide it exactly
  • A low-confidence path is safe
  • You can observe whether it was useful

It is overkill when

  • Code, math, or a lookup gives the answer
  • You need prose, planning, or open-ended research
  • A wrong action cannot be recovered or reviewed
  • The call is rare and changes no meaningful outcome
  • You cannot measure the decision after deployment
